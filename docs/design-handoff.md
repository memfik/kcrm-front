# kCRM (QMobile): редизайн — передача фронтенду

Готовый **HTML-дизайн** нового kCRM. Каждый файл — самостоятельная страница: открывается двойным кликом в Chrome, работает без интернета и без сервера. Логика в макетах настоящая (фильтры, формы, ссылки), но данные хранятся только в странице — в рабочей версии их нужно брать из API.

## 1. Как смотреть
1. Открыть **`00-Меню.html`** — все страницы с кнопками «Компьютер» и «Телефон». Или начать с **`01-Вход.html`** → «Войти» → **`02-Главная.html`**.
2. Дальше — по меню в шапке (6 разделов, мега-меню) или поиском **⌘K**.
3. Тема (светлая/тёмная) — кнопка в шапке или «Настройки».
4. Телефон: сузить окно до < 640 px (или DevTools → телефон) — меню уходит в бургер ☰.

## 3. Дизайн-система (как kSpot / ЕСТУ)
- Шрифт **Inter** (кириллица), `font-feature-settings: "cv11","ss01"`; табличные цифры **только** в числах (иначе Inter растягивает дефис).
- Цвета: фон `#0a0b0e` / светлая `#f4f6fb`, карточки `#14161b` / `#fff`, акцент `#085eff`, тёмный бренд `#001a9f`, рост `#3ddc84`, падение `#ff5257`.
- Стекло Opaline: `--glass-tint`, `--glass-rim`, `--glass-shadow` (значения — из `kspot-admin/src/app/globals.css`).
- Радиусы: карточки 22–24 px, поля 12 px, кнопки/чипы 999 px. Иконки — lucide.
- Ширина контента ограничена **1760 px** (на 2K/4K не растягивается).

## 4. Компоненты (сделать один раз)
`Header` + `MegaMenu` + `MobileMenu` · `CommandK` · `Notifications` / `Settings` / `UserMenu` (поповеры) · `PageHero` (крошки, заголовок, сводка словами, кнопки, переключатель Месяц/Квартал/Год) · `StatTile` (как в kSpot) · `ViewTabs` (Список / Аналитика) · `StatusTabs` · `DataTable` (галочки, №, сортировка, липкие колонки слева/справа, пагинация, вид «карточки») · `FilterChip` + `FilterDrawer` («Ещё») + `ActiveFilterChips` · `RecordPage` (просмотр записи — отдельная страница: вкладки слева, «Кратко»/ответственный/ссылка справа, ← назад, ‹ › соседние записи) · `FormPage` (создание/редактирование — отдельная страница) · `DeleteDialog` (обязательная причина + «Отменить») · `ShareDialog` · `ImportDialog` · `DelegateDialog`.

**Все списки — один шаблон**: страница описывается конфигом (колонки, фильтры, вкладки, KPI, карточка). Это видно в коде макетов — `const PAGE = {...}`.

## 5. Поведение
- **Сравнение периодов** везде: KPI показывают «▲/▼ % к прошлому месяцу/кварталу/году», графики — пунктир «год назад».
- **Ссылки на записи**: `#r-<id>[/<вкладка>]` — просмотр, `#e-<id>` — редактирование, `#new` — создание. В Next.js это стоит сделать маршрутами: `/deals/29741`, `/deals/29741/edit`.
- Удаление — только с причиной, в корзину, с отменой.
- Выбранный вид (список/карточки), вкладка «Список/Аналитика», тема — запоминаются (в проде — в профиле пользователя).

## 6. Данные
Поля и справочники — **из реальной базы kCRM** (копия 2016–2018): `cslist/csinfo`, `deals`+`actlist` (11 этапов), `comoffer/comofferchild`, `contracts`, `treqform`, `impdates`, `salesplan`, `inworkplan`, `abon_conn_check`, `acts`, `pricelist` (версия 12), `deal_cancel_list`, `statlist` и др.
Фото в шапках разделов убраны — фон только из фирменного свечения.
⚠️ Названия компаний, БИН и ФИО — **примеры** (в копии базы заглушки). Наряды, лиды, заявки IP, номера, тендеры, прогнозы и звонки — **примеры данных** (в копии этих таблиц нет данных), на страницах это подписано.

## 7. Важно по безопасности (старый kCRM)
`accenter.php` пишет логин и пароль открытым текстом в `0upload/css.css`, а SQL собирается из сырого ввода. В новой версии: только API с параметризованными запросами, вход через AD/SSO, пароли нигде не логировать.

## 8. Порядок работ
1. Токены, Header/MegaMenu/MobileMenu, ⌘K.
2. DataTable + фильтры + Drawer + формы на «Контрагентах».
3. Остальные списки — через конфиг.
4. Конструктор КП и договора, Свод по продажам, Главная.
5. Вход (живые обои из kSpot), Профиль.
